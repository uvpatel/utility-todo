# Utility Todo

Utility Todo is a Next.js app for a protected todo workspace with a dashboard-style interface. It uses Better Auth for authentication, GitHub OAuth for social login, Drizzle with PostgreSQL for auth persistence, shadcn/ui components, and Zustand for the client-side todo store.

## Features

- Landing page at `/`
- Login page at `/login`
- Protected todo workspace at `/todo`
- Dashboard view at `/dashboard`
- GitHub OAuth through Better Auth
- Email/password auth enabled in the server config
- Persisted browser todo state with Zustand
- Drizzle/PostgreSQL auth database configuration

## Tech Stack

- Next.js 16 App Router
- React 19
- TypeScript
- Tailwind CSS 4
- shadcn/ui and Radix UI
- Better Auth
- Drizzle ORM
- PostgreSQL, currently configured for Neon-compatible connection strings
- Zustand

## Getting Started

Install dependencies:

```bash
npm install
```

Run the development server:

```bash
npm run dev
```

Open the app at:

```txt
http://localhost:3000
```

## Environment Variables

Create local environment files as needed. `.env*` files are ignored by Git.

Required for auth/database:

```env
DATABASE_URL=postgresql://...
BETTER_AUTH_SECRET=replace-with-a-random-secret
BETTER_AUTH_URL=http://localhost:3000
GITHUB_CLIENT_ID=your-github-oauth-client-id
GITHUB_CLIENT_SECRET=your-github-oauth-client-secret
```

For local development, `.env.local` should contain:

```env
BETTER_AUTH_URL=http://localhost:3000
```

For production, set `BETTER_AUTH_URL` to the deployed app origin, for example:

```env
BETTER_AUTH_URL=https://utility-todo.vercel.app
```

## GitHub OAuth Callback URLs

The GitHub OAuth app must include the callback URL for the environment you are using.

Local callback:

```txt
http://localhost:3000/api/auth/callback/github
```

Production callback:

```txt
https://utility-todo.vercel.app/api/auth/callback/github
```

If GitHub shows `The redirect_uri is not associated with this application`, the callback URL generated by the app does not match the callback URL registered in the GitHub OAuth app.

## Database

Drizzle is configured in `drizzle.config.ts`.

Auth uses Better Auth's Drizzle adapter in `src/lib/auth.ts`. The auth route handler is located at:

```txt
src/app/api/auth/[...all]/route.ts
```

Generate Drizzle migrations after schema changes:

```bash
npx drizzle-kit generate
```

Apply migrations:

```bash
npx drizzle-kit migrate
```

## Deployment

The app can be deployed to Vercel as a standard Next.js project.

Set the production environment variables in Vercel, including `DATABASE_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `GITHUB_CLIENT_ID`, and `GITHUB_CLIENT_SECRET`.

Make sure the production GitHub OAuth callback URL exactly matches the deployed domain.
